# 讲自己的：把做过的事逼出具体来

这一批和 [system-design-cases/](../system-design-cases/) 是同一个形状 ——
**一份提示词，复制走，去别家大模型那里被追问** —— 但有一处不一样：

**材料是你带来的，底牌是我们写的。**

系统设计那批的底牌是「这道题的必答点」，模型拿它判你漏了什么知识。
这一批的底牌是**「这一类事的根因清单」**：你那次为什么延期，答案只有你知道；
但**延期的根因就那么五类，每一类有它自己的征兆** —— 那份清单是可以事先写死的，
模型拿它问你「你说的属于哪一类，其余四类查过没有」。

所以这一批的题目要足够具体才立得住。「复盘一个项目」写不出清单，
「复盘一次上线延期」就写得出 —— 这也是为什么下面**具体那几份排在前面、
通用那三份摆在最后当兜底**。

判卷线因此也换了一条。系统设计那批是「只讲收益不讲代价的答案，一定是背的」，
这一批是：**给不出具体的，就是空的。**

## 怎么用

1. 挑一份，**新开一个空对话**。
2. 把那个文件里 `---` 分隔线**之后**的全部内容复制过去。分隔线之前是给你看的说明。
3. **先用一两句话说出你要讲的是哪件事**（哪个项目、哪次故障、哪个方案），
   然后等它问 —— 这一点和系统设计那批不一样，那批是贴完什么都别说。
   `05-resume.md` 是把简历贴进去。
4. 中途三个口令：

   | 口令 | 作用 |
   | --- | --- |
   | `跳过` | 立刻进下一幕 |
   | `换一个` | 换个项目 / 换次故障 / 换条经历重来 |
   | `复盘` | 立刻跳到收尾，输出复盘卡片 |

   **没有 `提示` 和 `直说吧`** —— 这批的底牌是「这一类事的根因清单」，
   不是你那件事的答案。硬留着那两个口令，模型只会现编一个你的故事出来。
   你答不出来就是一条结论，它会如实记下来。

5. 结束时它会输出一张卡片，**存下来**。下次再做同一份时先不看，
   做完再对比 —— 上次那几条「下次要补的」补上了没有，比这次讲得好不好重要。

三条使用上的坑：

- **别在同一个对话里连做两份。** 上一份的上下文会让它对你有先入判断。
- **它开始安慰你的时候，提醒它看铁律里「不要夸我」那条。** 复盘和故障这两份
  尤其容易触发大模型的安抚人格 —— 那会让整件事变成情绪疏导，而不是复盘。
- **它想替你把答案圆回来的时候，打断它。** 你说「记不清了」，它接一句
  「可能是因为……吧」，那句就已经不是你的记忆了。

## 想用语音练？走 [oral/](oral/)

这一批的判卷线是「给不出具体的，就是空的」，**而语音把这条线变得更锋利**：
**沉默会被听见**（「最早哪一天你就知道要延期了」后面那几秒，比任何回答都诚实），
而且**你没有草稿**（打字时「配合有点问题」你会停下来斟酌措辞，
说出口的就是第一版）。

[oral/](oral/) 下面那 13 份最要紧的一条新规矩是：**它不许填补你的沉默** ——
这批是没有底牌的 Drill，最大的风险不是「答不出来」，而是
**你说「记不清了」，它接一句「可能是因为排期紧吧」，你一点头，
那句就变成了你的记忆**。
另外还有几张只有语音能开的账单：沉默账、「我们」计数、改口账、
计时（一条简历讲不讲得满三分钟）、以及「改这个数据的地方有几处，当场数」。

## 建议的路线

不用按编号刷，按你眼下要做的事挑：

- **手上有个方案要提** → 先在答辩那三份里找对得上的（重写 / 自研 / 加缓存），
  都不是就用 `03`。在评审会之前自己挨一遍问，比在会上被问住便宜得多。
- **刚延期 / 刚发现没人用 / 刚出过一次事故** → 对应那一份，趁记得住。
  故障和延期尤其要趁热做，时间线过一周就说不准了。
- **准备找工作** → `05` → `04`。先体检简历（它会告诉你哪几条撑不住），
  再拿撑得住的那几条去练行为面试。
- **想练「讲自己做过的东西」这件事本身** → 挑三四份做一遍，
  再去做系统设计那批里的
  [91-your-own-project.md](../system-design-cases/91-your-own-project.md)。

`01` 和 `91` 讲的可能是同一个项目，但目的不一样：`91` 是讲给别人听的（考可信度），
`01` 是讲给自己听的（考下一步）。

`01` 和 `91` 讲的可能是同一个项目，但**目的不一样，不是重复**：
`91` 是讲给别人听的（考可信度，目标是被相信你做过），
`01` 是讲给自己听的（考下一步，目标是找到一条你能改的动作）。
同一个项目两份都做，得到的东西不一样。

## 为什么这么写（几个决定）

- **口令砍成三个。** 底牌是「这一类事的根因清单」，不是你那件事的答案，
  所以「提示」和「直说吧」无从给起 —— 硬留着，模型会顺势编一个你的故事出来。
- **具体的排前面，通用的当兜底。** 这一批一开始只有三份通用的
  （复盘 / 答辩 / 面试），后来发现它们的底牌互相能换 ——
  那就说明它们是流程模板不是题（判据见
  [drill-authoring.md](../drill-authoring.md) 第零步）。
  所以补了具体场景，把原来那三份降格成兜底，没有下架。
- **每份都有一条「不要替我圆答案」。** 这是无底牌的 Drill 最大的风险：
  我说「记不清了」，模型接一句「可能是因为排期紧吧」，我一点头 ——
  那句就变成了我的记忆。这比答不出来糟糕得多。
- **复盘那两份都禁止把根因停在人身上。** 尤其故障那份，
  这条写成了铁律第 3 条：追到「为什么这个操作能把线上改坏」为止。
  停在「某人手滑」的复盘，下次还会发生。
- **简历那份明确不许模型代笔。** 代笔出来的句子你在面试现场撑不住 ——
  它只负责指出哪句有问题，改由你自己改，改完它再判。
- **不评价人。** 这几份都写了：不评价你这个人、你的团队、你的学校、
  你待过的公司，也不预测你能不能过面试。它判的是「这件事讲清楚了没有」，
  就这一件。
