# 数据库：一次只钻一块

和 [algorithms/](../algorithms/)、[computer-systems/](../computer-systems/) 同一个形状：
**一份提示词，复制走，去别家大模型那里被追问**，学习型 + 引导姿态
（先问你卡在哪一层 → 给脚手架不给答案 → 引导两次不通才讲，讲完要你复述）。
**「不许夸我」那条照旧。**

## 这个系列特有的两条

**一、默认按 MySQL / InnoDB 讲。** 数据库这块的坑有一半是实现细节
（间隙锁、聚簇索引、回表），跨家不通用。所以每一份的开头都写着
「我要是说了别家，按我说的那家讲，并且在结论不同的地方点出来」——
**用 PostgreSQL 的人照样能练，只是要在第一句话里说一声。**

**二、全程逼数量级。** 「快一些」「省了 IO」一律被打断：几行？几次？几倍？
说得出结论说不出数字，就是背的 —— 这一批练的就是这个
（同 computer-systems 那批）。

## 每一份只钻一块

粒度判据和别的系列一样：**把这一份的底牌拿到隔壁那份上去，还成立吗？不成立才写。**

所以这里没有「索引优化」「事务」这种题 —— 那种题的底牌只能写成
「注意选择率、注意锁」，挪到哪儿都成立。切出来的是
「联合索引的列顺序」「一条 UPDATE 锁了什么」「OFFSET 那一步做了什么」。

## 怎么用

1. 挑一份，**新开一个空对话**。
2. 把那个文件里 `---` 分隔线**之后**的全部内容复制过去。分隔线之前是给你看的说明。
3. **第一句话先说你用的是哪家、哪个版本**（不说就按 MySQL 8 讲），然后等它问。
4. 中途四个口令：`跳过` ｜ `换个说法` ｜ `直说吧` ｜ `复盘`。
5. **末尾的底牌别自己先读** —— 那一栏「常见的想错」写的就是每一问的答案。

## 建议顺序

前三份是地基，**「联合索引的顺序」尤其要先做** —— 后面几份里
「锁加在索引上」「扫描行数为什么这么大」都要用到它那句「叶子上是字典序」。
线上正在被并发问题咬的，直接从「先查再改」开始；查询慢的从「读了多少行」开始。
