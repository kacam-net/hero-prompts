# 算法：一次只钻一个技巧

这一批和 [system-design-cases/](../system-design-cases/) 是同一个形状 ——
**一份提示词，复制走，去别家大模型那里被追问** —— 但换了一种姿态：

**这一批是学习型的：它会引导你，不会追到你说不出话为止。**

系统设计那批是面试陪练，你答不上来是有效信息，教练不用管你；
这一批不一样 —— 学不会的人被追到底只会关掉窗口。所以每份提示词里的纪律是：
**先问你卡在哪一层**（没听过 / 知道但不明白为什么 / 明白但写不对），
再决定给什么；**给脚手架不给答案**；同一个点**引导两次还不通才直接讲，
讲完要你用自己的话复述一遍** —— 复述不出来就等于没学会。

**唯一跨所有系列不变的那条是「不许夸我」。** 引导不等于哄。

## 每一份只钻一个技巧

这批题的粒度是有意压到很小的：不是「排序算法」「动态规划」，
而是**「二分的边界」「DP 的状态定义」「回溯去重是同层还是同枝」**。

判据是：**把这一份的底牌拿到隔壁那一份上去，还成立吗？** 不成立才写。
「二分的不变量」挪到「单调栈」上完全不成立，所以它们是两道题；
而一份叫「二分查找」的题，底牌只能写成「注意边界、注意死循环」——
那样的东西你自己对模型说一句「你来考我二分」也能得到，我们就白做了。

## 怎么用

1. 挑一份，**新开一个空对话**。
2. 把那个文件里 `---` 分隔线**之后**的全部内容复制过去。分隔线之前是给你看的说明。
3. 什么都别说，等它问第一个问题。
4. **手推优先于写代码。** 这批题里每一份都写了这条纪律，它会打断你 ——
   在长度 2 的数组上把 `l` 和 `r` 推一遍，比写十遍模板管用。
5. 中途四个口令：

   | 口令 | 作用 |
   | --- | --- |
   | `跳过` | 立刻进下一幕 |
   | `换个说法` | 这一处换个角度再讲一遍（**这批特有的**） |
   | `直说吧` | 讲完整答案，然后要我复述 |
   | `复盘` | 立刻跳到收尾，输出复盘卡片 |

6. **末尾的底牌别自己先读。** 这批的底牌里那栏「常见的想错」，
   写的就是每一问的答案。

## 想用语音练？走 [oral/](oral/)

这一批的纪律是「手推优先于写代码」，**语音版把它变成了硬约束** ——
你连代码都写不了，只能推。而「手推」在语音里有了固定格式：
**报数**（二分的左右中）、**报窗口**、**报栈**、**报父节点**、**报前缀**、**报分支**。
含糊的「然后就缩小了」在打字时看着像回事，**说出口立刻听得出是空的**；
每份收尾都会报你有几步是含糊过去的。
另外变量记号全说中文，`03`、`05` 两份**不许查**——那本来就是心算考试。

## 建议的路线

不用按编号刷。

- **想不出解法** → 先 `08`（状态定义）。「看得懂题解、自己想不出来」
  一多半卡在这一步。
- **写得出但老是错边界** → `01` → `07`。这两份治的是同一种病：背公式而不是用定义推。
- **认不出题型** → `04` → `02`。这两份练的是「看见一道新题，认出它是哪个形状」。
- **面试要问复杂度** → `03`。它同时是 `04`（均摊）、`05`（缓存）、
  `10`（指数级怎么估）的地基，早做早受益。
- **贪心老是错** → `09`。它是唯一一类「跑过样例仍然可能彻底错」的算法。

几份之间是有引用关系的：`02` 里「有负数不能滑窗」的出路在 `07`；
`03` 里的均摊在 `04`、`06` 各出现一次；`08` 的「状态要能被完整表示」
和 `10` 最后一幕是同一条。**串着做比单独做划算。**

## 为什么这么写（几个决定）

- **姿态换了，但「不许夸我」没换。** 学习类必须引导，否则学不会的人直接走人；
  但引导不等于哄 —— 被肯定的感觉会盖掉「我漏了什么」。
- **每份都有一条「在我说出可行做法之前不许提到任何专有名词」。**
  这是学习类最大的风险：模型太急着展示知识，一上来就说「这道题用单调栈」，
  那你就再也没机会自己认出这个形状了。
- **底牌的形状变了：主体是「常见的想错」，不是知识点清单。**
  知识点模型自己就会，「学这块的人通常会怎么想错」才是我们要提供的。
- **每份都逼手推。** 算法这一类，写代码是最容易掩盖「其实没想清楚」的动作。
- **不做题海。** 十份题都是「技巧」不是「题目」—— 刷题去 LeetCode，
  这里练的是刷完之后你说不说得清为什么。
