## 怎么用

1. 挑一道题，**新开一个空对话**（别在聊过这道题的对话里开，模型会顺着旧答案走）。
2. 把那个文件里 `---` 分隔线**之后**的全部内容复制过去。分隔线之前是给你看的说明，
   不用贴。
3. 什么都别说，等它问第一个问题。
4. 中途有四个口令随时能喊：

   | 口令 | 作用 |
   | --- | --- |
   | `跳过` | 立刻进下一幕 |
   | `提示` | 给一个方向，但不给答案 |
   | `直说吧` | 讲这一点的完整答案，然后继续追问代价 |
   | `复盘` | 立刻跳到收尾，输出复盘卡片 |

5. 结束时它会输出一张复盘卡片，**存下来**。下次重做同一题时先不看，做完再对比 ——
   两次的 ❌ 有没有变少，比第一次答得好不好重要得多。

三条使用上的坑：

- **别在同一个对话里连做两道题。** 上一题的上下文会让它对你的水平有先入判断，
  第二题的判卷就不准了。
- **别在它问完之后立刻搜答案。** 卡住 30 秒说不出来，本身就是一条有效信息。
- **它开始夸你的时候，提醒它看铁律第五条。** 大模型的默认人格会不断肯定你，
  那会让整件事变成自我感觉良好，而不是学习。

## 想用语音练？走 [oral/](oral/)

系统设计**本来就是一边说一边被追问** —— 真实面试里唯一多出来的是一块白板，
而 [oral/](oral/) 下面这 17 份**连白板都没有**：
你一说「我画一下」，它就回「我看不见，说给我听 —— 一站一站说，谁调谁」。
**框图最擅长藏的就是「这两个东西到底谁调谁」。**

另外新加了两张账：**我是几秒之内开始讲方案的**（没问清楚就开讲是最稳定的失分项），
以及**我有几次在报菜名**（念一串中间件却说不出为什么需要它）。
容量估算一律当场心算，不许查。

## 建议的路线

不要按编号顺序刷。按这个走：

1. **先做 [90-cross-cutting-drill.md](90-cross-cutting-drill.md)。** 它是零件测试。
   零件不熟的话，做案例题时你会把时间花在临时想「幂等怎么做」上，而不是花在这道题
   本身的矛盾上。
2. **再做 04（短链）**。最简单，用来熟悉这套流程和口令，别一上来就啃支付。
3. **然后按你的方向挑**：面交易/金融挑 01 → 02 → 03；面社交/内容挑 05 → 06 → 07；
   面基础架构挑 10 → 13 → 12。
4. **最后做 [91-your-own-project.md](91-your-own-project.md)**，而且要反复做。
   playbook 里说得很清楚：「有没有真的做过」最难伪装，也最值钱。

## 为什么这么拆（做的时候的几个决定）

- **每个文件自包含，宁可重复。** 铁律和流程骨架在 17 个文件里几乎一模一样。
  按理该抽出去，但使用方式是「复制一个文件贴过去」——抽出去就变成要贴两个文件，
  或者贴过去一半是没展开的引用。可读性输给可用性。
- **底牌放在文件末尾，并且明确标注「未经我说出不得透露」。** 这是整套提示词唯一真正
  重要的机制。没有它，模型的默认行为是收到题面就把标准答案铺开讲一遍 ——
  那你学到的是「读了一遍」，不是「自己推出来过」。
- **「不许夸我」写成硬规则。** 大模型的默认人格会不断肯定，这在学习场景里是负作用：
  你会记住那种被肯定的感觉，而不是记住自己漏了什么。
- **每题都强制「说出代价」。** playbook 开头那句判断标准 ——
  「只讲收益不讲代价的答案，一定是背的」—— 是整份文档的判卷线，所以它进了每一个文件。
- **横切套路没有做成 12 个文件。** 单独考「什么是幂等」只会得到一段名词解释。
  它们只有嵌在具体案例里、或者以「第二层追问」的形式连珠炮问出来，才考得出东西。

## 素材的边界

这批文件里的「底牌」都来自 playbook，没有额外发挥。如果你发现模型讲了底牌之外的东西，
那是它自己的知识，**不一定对** —— 尤其是具体数字（某个中间件的吞吐、某个 API 的行为）。
拿它当讨论的素材，别当结论。
