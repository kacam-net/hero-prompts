# 产品设计 · 语音版：说不出数字的时候，沉默很响

[上一层](../README.md) 那 17 份是打字用的。这里是同样 17 道题的**语音版**。

产品设计这一批的判据是三条：**说得出这是谁的什么问题（而且有证据）、
说得出怎么算成功（而且那个数现在是多少）、说得出代价和你放弃了什么。**

**这三条在语音下都变严了**，原因很简单：
打字的时候，「效果会更好」「很多人有这个痛点」这类话写出来会被自己删掉一遍；
**说出口就留在那儿了——而且对面会立刻回你一句「多少？」。**

## 语音版加了什么

**一、几张只有语音能开的账单。** 收尾时会报给你：

| 账单 | 出现在 | 它抓的是 |
| --- | --- | --- |
| **模糊词账** | [01](01-north-star.md) | 「效果会更好」「用户会喜欢」说了几次，哪一段最密 |
| **我猜了几次** | [05](05-retention.md) | 没看数据就抛原因的次数，每次引原话 |
| **第几秒开始报数字** | [04](04-pricing.md) | 还没说清「按什么计价」就先报价格 |
| **空话账** | [15](15-who-pays.md) | 「很多人」「市场很大」背后有没有具体的东西 |
| **趋势词账** | [16](16-why-now.md) | 「这是大趋势」说出口时你自己都听得见它有多空 |
| **名字关** | [17](17-first-ten.md) | 报到第几个开始卡壳、中间停了多久 |
| **异常路径记分** | [10](10-feature-spec.md) | 那十问你事先想到几个 |
| **三问关** | [14](14-team-metrics.md) | 每个指标的三问答齐了没有（多数人漏第三问） |

**二、所有数据由它念给你听。** 报告、分布、分渠道的表格，
**一行一行念、每行停半拍**，念完问你一句「记住了吗」。

这改变了几道题的难度：
[08](08-ab-test.md) 那份实验报告里「同时看了十八个指标」只是一句飘过去的话，
**打字版你一眼就扫到了，听的时候得当场反应**；
[12](12-conversion.md) 的「注册其实从三万掉到两万」，
**那两个数中间隔着好几秒，你得自己把它们接起来**；
[13](13-satisfaction.md) 的最低分那一档，**是在你听完五档之后才浮出来的**。

**三、要你当场把话说出口。** 周报怎么写（[11](11-dau.md)、[12](12-conversion.md)）、
下线公告怎么说（[09](09-sunset.md)）、怎么回老板（[08](08-ab-test.md)、[14](14-team-metrics.md)）、
提示文案怎么写（[10](10-feature-spec.md)）——
**写出来的能改五遍，说出来的只有一遍。**

## 怎么用（豆包）

1. 挑一道题，**新开一个空对话**，把 `---` 之后的全部内容粘贴进去
   （或者存成一个智能体的人设）。
2. **切到语音通话**，说一句「开始吧」。**然后等它问，别抢答。**
3. 口令直接说出来：「跳过」「提示」「直说吧」「再念一遍」「捋一遍」「复盘」。
4. **手边留张纸**——它念的那些数你得自己记着。
5. **末尾的底牌别自己先读。**

## 建议的路线

1. **先做 [01](01-north-star.md)。**「怎么算成功」是后面所有题的地基。
2. **然后按你眼下的事挑**：
   需求排不动走 [02](02-prioritization.md)；
   留存在掉走 [05](05-retention.md) → [06](06-onboarding.md)；
   要定价或冷启动走 [04](04-pricing.md) / [03](03-cold-start.md)；
   天天写需求文档走 [10](10-feature-spec.md)，**而且反复做**。
3. **[08](08-ab-test.md) 留到后面**，它是这一批里**语音收益最大的一份**。
4. **那三份商业点子题，最好在你真的有一个点子的时候做。**
   [17](17-first-ten.md) 尤其——**它只要你报十个名字，
   而你报到第四个的时候就已经知道答案了。**
