# hero-prompts

[看开网 Kacam.net](https://kacam.net) 练功房（[kacam.net/drills](https://kacam.net/drills)）
的提示词正文。**这里是内容的唯一事实来源** —— 改题目改这里，站上那份跟着走。

一份提示词就是一道题：复制走，贴给 ChatGPT / Claude / DeepSeek / 豆包，
它当考官逐幕追问你，而不是把答案倒给你。所以这个板块**不调大模型、不扣积分** ——
答的是别人家的模型。

## 语音版：`oral/`

**九个系列各有一份 `oral/`，一共 94 份**，给豆包这类支持**语音通话**的模型用。
**知识点一个没少，底牌一个没改**，改的是它怎么说、怎么问、怎么判：
下划线、代码块、表格、`✅🟡❌` 念出来全是噪音，
所以列名说中文、SQL 和代码口述、判卷符号改口播，
另外每一份都加了一组语音铁律（**每次不超过三句就得停、不许念清单、
不许报菜名、容忍语音转文字的错别字**）。

| 语音版 | 份数 | 语音下多出来的东西 |
| --- | --- | --- |
| [speaking/oral/](speaking/oral/) | 7 | **真的沉默三到五秒**、真的打断、老板只听你三十秒 |
| [troubleshooting/oral/](troubleshooting/oral/) | 6 | 一次只答一个问题；要图就念给你听；多了「捋一遍」 |
| [english/oral/](english/oral/) | 5 | 音标不念符号、直接发音；**它听得见你把 V 读成 W** |
| [database/oral/](database/oral/) | 8 | 列名说中文、执行计划一项一项念、时间线改「报拍子」 |
| [computer-systems/oral/](computer-systems/oral/) | 10 | **不许查**：先按你现在记得的说一个数量级 |
| [algorithms/oral/](algorithms/oral/) | 10 | 手推变成**报数、报栈、报分支** |
| [system-design-cases/oral/](system-design-cases/oral/) | 17 | **连白板都没有**；不许报菜名；容量估算当场心算 |
| [product-design-cases/oral/](product-design-cases/oral/) | 17 | 模糊词账、「我猜了几次」、数据一行一行念给你听 |
| [your-own/oral/](your-own/oral/) | 14 | **它不许填补你的沉默**；沉默账、「我们」计数、改口账 |

**只有 [code-review/](code-review/) 没做语音版** —— 它的核心是读一段二十几行的代码，
纯语音要么得让教练分段念给你听（记不住），要么就得改成
「代码看屏幕、追问走语音」的混合模式。那是改设计，不是改措辞。

## 一份 md 长什么样

格式只有一条约定：

```
# 标题                      ← 站上的题名从这里取
> 给读仓库的人看的说明块      ← 不解析，也不会出现在站上
---                        ← 单独一行
提示词全文                   ← 从这里到文件末尾，就是复制给大模型的那一整段
## 底牌                     ← 也在里面，它是给模型判卷用的
```

**「第一个 `---` 之后的全部内容」就是用户复制走的那段**，包括末尾的底牌。
所以 `---` 之前随便写给自己人看，`---` 之后每一个字都会被模型读到。

## 三条不能破的

1. **底牌是这套东西唯一的护城河。** 站上的页面**一个字都不渲染提示词正文**，只出手写的、
   不剧透的介绍。用户不知道自己该被问什么 —— 写死的必答点清单才是他给不了自己的。
   所以别把底牌写进 issue 标题、别在别处贴出来。
   （`## 评分维度` 是有意公开的例外：那种题考的是当场表现，知道按哪几维打分泄露不了答案。）
2. **一份 Drill 是一道题，不是一套流程。** 判据：**把这一份的底牌挪到同系列另一份上，
   还成立吗？成立就说明粒度太粗。** 详见 drill-authoring.md 第零步。
3. **姿态跟着系列走。** 面试那套拷问（提示两次才讲、答不上来是正常结局）用在学习类
   （算法、计算机系统、数据库、英语）上会毁掉它 —— 学不会的人被追到底只会关掉窗口。
   学习类要引导。**「不许夸我」是唯一跨所有姿态的那条。**

## 怎么改

- **优化已有的提示词** —— 直接改那份 md，提 PR。改完自己贴给一个大模型走一遍，
  PR 里说一句哪里卡住了、改完好在哪。
- **加一道新题** —— 先读 drill-authoring.md 过一遍粒度判据，md 放进对应目录、提 PR。
  站上要不要上架、摆在哪一组、难度和时长写什么，是另一半（策展清单），
  在主仓库里由维护者补一行 —— **所以新题合并进来不等于站上立刻能看到**。
- **别在这个仓库里找网站代码。** 站是另一个仓库，这里只有内容。
  文中偶尔提到的 `AGENTS.md`、`DrillSeries`、`db/drills/*.yml` 都是那边的东西。
