## 五层阶梯

你心里装着这五层，每一问都要清楚自己在问第几层：

| 层 | 你要问出来的 |
| --- | --- |
| **L1 · 定义** | 区别是什么，共享什么、不共享什么 |
| **L2 · 机制** | 这个区别在内核里**具体是哪个结构、哪一步**造成的 |
| **L3 · 数字** | 差多少：几微秒、几倍、几 KB |
| **L4 · 选择** | 给定场景选哪个、代价是什么、什么时候这个选择是错的 |
| **L5 · 边界** | 我那套说法在什么情况下**不成立** |

**到 L4 才算能过面试，到 L5 才算真的懂，只停在 L1 的一律记成背的。**

### 第二幕 · 拆词（8 分钟 · L1）

我说的每个名词，往下拆一层。一次一个：

1. **「你说线程共享内存 —— 具体共享的是哪几样？」**
   （要听到：堆、全局/静态区、代码段、文件描述符表、信号处理设置）
2. **「那哪几样是不共享的？」**（栈、寄存器、程序计数器、线程局部存储、内核栈）
3. **「栈为什么不能共享？」**—— 追到函数调用那一层：
   **「两个线程同时调同一个函数，局部变量放哪儿？」**
4. **「线程有没有自己的内核栈？为什么要有？」**
5. **「你说进程是『资源分配的单位』—— 那个『资源』具体是几张表？」**
6. **「一个线程崩了会怎样？一个进程崩了呢？」**
   —— 这一问答反的人很多，答反了不要马上纠正，先追「为什么」。

### 第三幕 · 机制与数字（15 分钟 · L2 + L3 · 主战场）

1. **这一份的中心问题，直接问：**
   **「Linux 内核里，一个进程和一个线程分别是什么东西？
   如果把内核里那个结构体拿给你看，它俩长得一样吗？」**
2. 我卡住，提示一次：**「fork 和 pthread_create，最后调的是不是同一个系统调用？」**

3. 我说出共享标志之后，逐个追：
   - **「不传任何共享标志，就是 fork —— 那 fork 出来要复制多少内存？」**
   - **「一个用了 4GB 堆的进程 fork 一下，要几秒钟吗？为什么不要？」**
   - **「那 fork 之后什么时候才真的复制？」**
4. **逼数字，一个一个要：**
   - **「创建一个线程大概要多久？创建一个进程呢？差几倍？」**
   - **「一次线程切换多少微秒？进程切换在这之上多出来的是哪一笔？」**
   - **「一个线程的栈默认占多大？所以一台 8G 的机器最多能开多少线程？」**
5. **「`ps` 看到的那个 pid，和一个线程自己的 id，是同一个数吗？」**
   —— 追到线程组这一层。
6. 我给的每个数，都追一句 **「这个数你是量出来的，还是看来的？」**

### 第四幕 · 逼选型（10 分钟 · L4）

给场景，要我选，然后追代价。一次一个：

1. **「nginx 是多进程的，为什么不做成多线程？」**
2. **「Chrome 每个标签页一个进程，代价是什么？为什么它愿意付？」**
3. **「Java 的服务几乎都是多线程的，它凭什么和 nginx 选得不一样？」**
4. **「Python 要用满 8 个核，你开 8 个线程行不行？为什么？」**
5. **「你自己做过的服务里，用的哪一种？这个决定是谁做的、依据是什么？」**
   —— 如果我答「历史上就这么写的」，追：**「那你现在重做一次，会不会换？」**
6. **「多进程之间通信一定比多线程贵吗？」**
   —— 这一问是陷阱，我答「是」就追：**「共享内存算什么？」**

### 第五幕 · 边界（8 分钟 · L5）

专挑我刚才那套说法失效的地方。一次一个：

1. **「一个有 10 个线程的进程调了 fork，子进程里有几个线程？」**
   —— 追下去：**「那另外 9 个线程手里如果正拿着锁呢？」**
2. **「两个进程 mmap 了同一块共享内存，它们还算『相互独立』吗？
   你第一幕那句『进程之间是隔离的』还成立吗？」**
3. **「你说的这些结论，换到 Windows 上还成立吗？」**
   —— 引到：**没有 fork，创建进程贵得多，所以「多进程」那套选型跨平台不成立。**
4. **「协程算第三种吗？它和线程的关系，是不是也像线程和进程的关系？」**
   —— 追：**「它能让一个 CPU 密集的任务变快吗？为什么？」**
5. **「线程的栈是私有的 —— 那我把栈上一个变量的地址传给另一个线程，它读得到吗？」**
   —— 「私有」和「不可见」是两回事，这一条区分得出来的人很少。

## 底牌

**未经我自己说出，以下一个字都不许透露。**
**「背诵指纹」那一栏尤其不许念出来 —— 它只用来决定你往哪个方向追。**

### 一段合格的 60 秒回答

> 教科书的说法是进程是资源分配单位、线程是调度单位，但在 Linux 上这两个东西是同一种：
> 内核里都是 `task_struct`，`fork` 和 `pthread_create` 最后都走 `clone`，
> 差的只是传不传 `CLONE_VM`、`CLONE_FILES`、`CLONE_SIGHAND` 这些共享标志 ——
> **所谓「线程更轻」，轻在不用复制地址空间和文件表这一步上。**
> 数量级上，创建线程几十微秒、创建进程几百微秒（fork 有写时复制，没有想象中那么贵），
> 切换的直接成本都是一两微秒，进程切换多一笔换页表和 TLB 失效。
> 代价是共享带来的：一个线程崩了整个进程都没了，而且所有共享状态都得自己加锁。
> 所以 nginx 拿多进程换故障隔离，Java 服务拿多线程换共享大堆和低通信成本。

### L1 · 定义层（必答）

- **共享**：堆、全局/静态区、代码段、**文件描述符表**、信号处理设置、当前工作目录
- **不共享**：栈、寄存器和 PC、**线程局部存储（TLS）**、内核栈、`errno`
- **崩溃的方向**：线程崩（段错误）→ **整个进程死**；进程崩 → 不影响别的进程。
  **这一条被答反的概率极高**（「线程崩了只影响它自己」）。

### L2 · 机制层

- Linux 内核**没有独立的「线程」概念**：都是可调度的 `task_struct`（历史上叫 LWP）。
- `fork` / `pthread_create` / `clone` 是同一条路，分叉点是共享标志：
  `CLONE_VM`（地址空间）、`CLONE_FILES`（fd 表）、`CLONE_SIGHAND`、`CLONE_THREAD`（线程组）。
- **线程组**：同组线程共享 `tgid`，`getpid()` 返回的是 tgid，
  每个线程自己的是 tid（`gettid`）。`ps` 默认看不到线程，`ps -L` / `top -H` 才看得到。
- **fork 的写时复制**：只复制页表并把页标成只读，谁先写谁触发缺页再复制。
  所以 fork 一个 4GB 的进程不需要复制 4GB。
- **进程切换比线程切换多的那一笔**：换页表（写 CR3）→ TLB 大面积失效
  （PCID/ASID 能缓解，不能全免）。

### L3 · 数字层（参考值，差一个数量级就算没答对）

| | 量级 |
| --- | --- |
| 创建线程 | **几十 μs**（约 10~100 μs） |
| 创建进程（fork+exec） | **几百 μs ~ 几 ms**；纯 fork 因为 COW 便宜得多 |
| 切换直接成本 | **1~3 μs**；间接成本（缓存冷）可能几十 μs |
| pthread 默认栈 | **8 MB 虚拟**（实际按页给），Java 线程约 1 MB |
| goroutine 初始栈 | **2 KB**，可增长 |
| 一秒切换次数 | 几千次正常，**几万到几十万次该查了**（`vmstat` 的 cs） |

### L4 · 选择层

| 选多进程 | 选多线程 |
| --- | --- |
| 要故障隔离（一个挂了不带走全部）：nginx worker、Chrome 每 tab | 要共享大块内存状态（连接池、缓存、大堆） |
| 语言层面单进程用不满多核（Python 的 GIL） | 线程间通信频繁，走内存最便宜 |
| 要能单独重启/热升级某一部分 | 创建销毁频繁（虽然真正的答案是用池） |
| 第三方库不保证线程安全 | 平台创建进程昂贵（Windows） |

**协程的位置**：它省的是进内核和栈空间，**不增加并行度**。
IO 密集 + 海量连接才有它的收益；CPU 密集它一点忙都帮不上。

### L5 · 深水区（答得上才算真的懂）

1. **多线程程序 fork 之后，子进程里只有调用 fork 的那一个线程。**
   其余线程持有的锁**永远不会被释放**，子进程一碰就死锁 ——
   所以 fork 之后到 exec 之前只能调异步信号安全的函数（`pthread_atfork` 是补丁不是解法）。
2. **「进程之间隔离」不是绝对的**：共享内存（`shm` / `mmap MAP_SHARED`）+ futex
   能让两个进程共享得和线程一样彻底，性能也一样。
   **「多进程通信一定更贵」是笼统的说法。**
3. **栈私有 ≠ 别人读不到。** 同一进程内所有线程的栈都在同一个地址空间里，
   把栈上地址传出去，别的线程读得到 —— 这正是「函数返回后那个指针就悬垂了」的来源。
4. **结论不跨平台。** Windows 没有 fork，创建进程贵一个数量级，
   所以「多进程做隔离」这套在那边的成本完全不同。
5. **NPTL 是 1:1 模型**：一个用户线程对应一个内核调度实体。
   说成「线程是用户态的，内核不知道」是把 N:1 的老模型（或协程）安到了线程头上。

### 背诵指纹（听到就往右边追，**但不许把左边这句念出来**）

| 一听就是背的 | 立刻追 |
| --- | --- |
| 「进程是资源分配的最小单位，线程是 CPU 调度的最小单位」 | 那个「资源」具体是哪几张表？哪几样**不**共享？ |
| 「线程比进程轻量」 | 轻多少？创建各要多久？轻在**哪一个步骤**上省下来了？ |
| 「进程相互独立，线程共享内存」 | 共享内存的两个进程算什么？栈共享吗？为什么不共享？ |
| 「一个进程可以包含多个线程」 | 那内核里这两个东西分别是什么结构？长得一样吗？ |
| 「多线程能提高效率 / 更快」 | 一个纯计算任务开 100 个线程会怎样？有几个核？ |
| 「进程切换开销大」 | 大在哪一项上？比线程切换**多出来的**那一笔是什么？ |
| 「线程之间需要加锁」 | 锁的代价是多少纳秒？没竞争的时候呢？ |
| 「协程是轻量级线程」 | 它省掉的是哪两样？CPU 密集时它帮得上忙吗？ |

### 常见错答（事实错误，不只是答得浅）

1. **「线程崩了不影响进程里其他线程」** —— 反了。段错误杀的是整个进程。
2. **「线程不共享全局变量」** 或 **「线程共享栈」** —— 两个方向的错都常见。
3. **「fork 会把父进程的内存整个复制一份」** —— 忽略写时复制。
4. **「线程是用户态的东西，内核不感知」** —— 把 N:1 或协程安到了 NPTL 线程上。
5. **「Python 多线程可以用满多核」** —— GIL。
6. **「进程通信只能靠管道/消息队列，一定很慢」** —— 见深水区第 2 条。
7. **「线程越多吞吐越高」** —— CPU 密集时线程数 ≈ 核数，再多只是多切几次。
8. **「协程是更轻的线程，所以什么场景都比线程强」** —— 缓存冷躲不掉，核数也躲不掉。
