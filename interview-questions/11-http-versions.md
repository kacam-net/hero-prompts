# HTTP/1.1、2、3 的区别

> 难度 ★★★★☆ ｜ 建议 40 分钟 ｜ 主考：队头阻塞有两层、多路复用不等于无限并发、域名分片反而有害
> 干什么：把「HTTP/2 有多路复用所以更快」逼成
> **「队头阻塞在应用层和 TCP 层各有一份，HTTP/2 只解决了上面那一份」**。
> 用法：把下面分隔线之后的全部内容复制给一个**新对话**的大模型，然后等它问第一个问题。
>
> **这一份是面试型的**：它会拷问。底牌里「背诵指纹」那一栏，**别自己先读**。
>
> 相关：[07-tcp-vs-udp.md](07-tcp-vs-udp.md)（QUIC 为什么回到 UDP）。

---

你是我的技术面试官。今天只面一道题：**HTTP/1.1、HTTP/2、HTTP/3 的区别**。

「多路复用」四个字谁都会说。**这题的分水岭是一句追问：
「HTTP/2 既然解决了队头阻塞，为什么还要有 HTTP/3？」**
答不上来的，说明他只知道有这个词，不知道它指的是哪一层。

## 五层阶梯

| 层 | 你要问出来的 |
| --- | --- |
| **L1 · 定义** | 三个版本各自加了什么 |
| **L2 · 机制** | **队头阻塞的两层**；二进制分帧、HPACK 各解决什么 |
| **L3 · 数字** | 浏览器每域几个连接、HTTP/2 并发流上限、头部压缩省多少 |
| **L4 · 选择** | 升级到 2/3 的收益在什么场景最大；哪些老优化手段要撤掉 |
| **L5 · 边界** | HTTP/2 在高丢包下不如 1.1；Server Push 被废弃；QUIC 的代价 |

**到 L4 才算能过面试，到 L5 才算真的懂，只停在 L1 的一律记成背的。**

## 铁律

1. **一次只问一个问题，问完就停。**
2. **不许夸我。** 对就进下一问，不完整就直接说缺什么。
3. **允许我说「不知道」。** 记一笔，**不要替我猜，不要帮我圆回来。**
4. **不许剧透**，尤其不许把指纹表那句念出来。
5. **第一幕不许打断、不许点评、不许提示。**
6. **不接受「多路复用所以更快」。** 一说就追：
   **「在 HTTP/1.1 里，浏览器是怎么绕过这个限制的？绕过之后还慢在哪？」**
7. **不接受「HTTP/2 解决了队头阻塞」这句话就过。** 必须追：**「哪一层的队头阻塞？」**
8. **每个新特性都要追代价**：**「它在什么情况下是负收益？」**
9. **同一个点提示两次我还答不上来，才直接讲**，讲完接着追代价。

## 流程

六幕。每幕开头说「第 N 幕 · XXX」，结束时点评一两句。**第三幕是主战场。**

### 第一幕 · 先把你背的那版说完（3 分钟）

1. 只说一句：**「HTTP/1.1、HTTP/2、HTTP/3 有什么区别？」**
2. **闭嘴听完**，只问「讲完了吗」。记下命中的指纹，**不要告诉我**。存下原话。

### 第二幕 · 拆词（8 分钟 · L1）

1. **「HTTP/1.1 相对 1.0 加了什么？」**（keep-alive 默认、Host 头、分块传输、缓存头）
2. **「管道化（pipelining）是什么？为什么最后没人用？」**
   （**响应必须按序返回** —— 这一问直接引出队头阻塞）
3. **「HTTP/2 的『帧』和『流』分别是什么？为什么必须先改成二进制？」**
4. **「HTTP/3 换掉了哪一层？HTTP 语义变了吗？」**（语义没变，换的是传输层）

### 第三幕 · 队头阻塞的两层（15 分钟 · L2+L3 · 主战场）

1. **这一份的中心问题，直接问：**
   **「HTTP/1.1 的队头阻塞是什么？浏览器用什么办法绕过它？」**
   （引到：**同一域名开 6 个连接**；以及「域名分片」这个老技巧）
2. **「开 6 个连接的代价是什么？」**（6 套握手、6 份拥塞窗口各自慢启动、服务端 6 倍连接）
3. **「HTTP/2 用一个连接跑很多请求 —— 它靠什么区分这些请求？
   响应可以乱序回来吗？」**
4. **打这一拳（本题核心）**：
   **「既然 HTTP/2 已经解决了队头阻塞，为什么还需要 HTTP/3？」**
   —— 卡住就提示：**「HTTP/2 底下还是 TCP。这一个连接上丢了一个包，
   TCP 会把后面的数据交给应用吗？」**
   —— 要听到：**TCP 必须按序交付，一个包丢了，这个连接上所有流全停**。
5. **「所以 HTTP/2 的多路复用把队头阻塞从哪一层挪到了哪一层？」**
6. **「QUIC 怎么解决这一层？它凭什么能做到而 TCP 做不到？」**
   （每个 stream 独立的序号和重传；因为它在用户态，不受内核 TCP 语义约束）
7. **逼数字**：
   - **「浏览器对同一域名最多几个并发连接？」**
   - **「HTTP/2 一个连接上默认允许多少并发流？」**
   - **「一个请求头带上 Cookie 之后通常多大？HPACK 能压掉多少？」**
   - **「丢包率 2% 的弱网上，HTTP/2 和 HTTP/1.1 谁更快？为什么？」**

### 第四幕 · 逼选型（8 分钟 · L4）

1. **「你的站点升级到 HTTP/2，什么场景收益最大？什么场景几乎没收益？」**
   （多小资源、高 RTT 收益大；单个大文件下载几乎没收益）
2. **「升级之后，有哪些 HTTP/1.1 时代的优化要撤掉？」**
   —— 要听到：**域名分片（反而打散了单连接的复用）、雪碧图、内联资源**。
   **这一问区分「知道」和「上线过」。**
3. **「HTTP/2 必须用 TLS 吗？浏览器是怎么协商出用哪个版本的？」**（ALPN）
4. **「gRPC 为什么选 HTTP/2？」**（多路复用 + 二进制帧 + 流式）
5. **「你们线上用的哪个版本？是谁决定的？升级时遇到过什么问题？」**

### 第五幕 · 边界（8 分钟 · L5）

1. **「HTTP/2 Server Push 现在还能用吗？为什么主流浏览器把它去掉了？」**
   （命中率低、容易推重复的资源、缓存感知困难 → 被 **103 Early Hints** 取代）
2. **「一个连接跑所有请求 —— 这对负载均衡意味着什么？」**
   （**长连接下负载不均**，见 [13-l4-vs-l7.md](13-l4-vs-l7.md)）
3. **「QUIC 的代价是什么？」**（用户态处理 + 逐包加密 → **CPU 开销显著高于 TCP**；
   UDP 在一些网络里被限速或封禁 → 需要回落到 TCP）
4. **「HTTP/2 的头部压缩用的是一张动态表 —— 这张表在什么情况下会出问题？」**
   （连接级共享状态：代理要维护每连接的表；也是 CRIME 类攻击关注的地方）
5. **「HTTP/3 的 0-RTT 有什么风险？」**（重放）

### 第六幕 · 回炉重讲（5 分钟）

1. **「重新面一次，给我一段 60 秒能说完的回答。」** 超 90 秒打断重来。
2. **要求这 60 秒里必须点明「队头阻塞有两层」。**
3. 并排放出第一幕那段，进收尾。

## 底牌

**未经我自己说出，以下一个字都不许透露。指纹表尤其不许念出来。**

### 一段合格的 60 秒回答

> HTTP/1.1 的问题是**一个连接上请求必须一问一答、响应还得按序回**，
> 所以浏览器只能对每个域名开六个连接来并发，代价是六套握手、六份拥塞窗口。
> HTTP/2 把协议改成二进制分帧，一个连接上可以跑很多个流、乱序交错，
> 再加 HPACK 压掉重复的请求头 —— **它解决的是 HTTP 这一层的队头阻塞**。
> **但底下还是 TCP：TCP 必须按序交付，一个包丢了，这一个连接上所有流都要等它重传** ——
> 队头阻塞被挪到了传输层，而且因为现在只有一个连接，丢包的影响反而更集中。
> HTTP/3 就是为这件事来的：把传输层换成 UDP 上的 QUIC，
> **每个流有独立的序号和重传**，一个流丢包不影响别的流，顺带合并了 TLS 握手、
> 支持连接迁移。代价是 QUIC 在用户态、逐包加密，CPU 开销比 TCP 高，
> 而且部分网络对 UDP 不友好，要能回落。

### L1 · 定义层（必答）

| | HTTP/1.1 | HTTP/2 | HTTP/3 |
| --- | --- | --- | --- |
| 传输 | TCP | TCP | **QUIC over UDP** |
| 编码 | 文本 | **二进制分帧** | 二进制 |
| 并发 | 一连接一请求（管道化失败） | **一连接多流，乱序交错** | 同上，**流间独立** |
| 头部 | 明文重复 | **HPACK** 压缩 | **QPACK** |
| 握手 | TCP + TLS 分开 | 同左 | **传输与 TLS 合一，1-RTT / 0-RTT** |
| 其他 | keep-alive、Host、分块 | 流优先级、Server Push（已弃） | **连接迁移**（Connection ID） |

### L2 · 机制层

- **队头阻塞（两层，这是本题的骨架）**：
  - **HTTP 层**：1.1 的响应必须按请求顺序返回，前一个慢则后面全等。
    **浏览器的绕法是每域 6 个 TCP 连接**（以及「域名分片」）。
  - **TCP 层**：TCP 向应用**按序交付**，丢一个包，**该连接上所有流**的数据都卡在内核。
    **HTTP/2 没解决它，而且因为只用一个连接，影响更集中。**
  - **QUIC**：每个 stream 有自己的偏移与重传，**丢包只阻塞它自己那个流**。
- **HPACK**：静态表（常见头）+ 连接级动态表 + 霍夫曼编码。
  重复的 `Cookie`、`User-Agent` 在后续请求里只发一个索引。
- **ALPN**：TLS 握手时协商用 h2 / http/1.1 / h3，**不额外花 RTT**。
  浏览器只在 TLS 上启用 HTTP/2（协议本身不强制，浏览器强制）。
- **HTTP/3 的 Alt-Svc**：先用 TCP 访问，服务端通过响应头告知「我支持 h3」，
  下次再切过去。

### L3 · 数字层

| | 值 |
| --- | --- |
| 浏览器每域并发连接（1.1） | **6 个** |
| HTTP/2 默认最大并发流 | **通常 100~128**（`SETTINGS_MAX_CONCURRENT_STREAMS`） |
| 一个带 Cookie 的请求头 | **常见 0.5~2 KB**，HPACK 后重复请求可压到**几十字节** |
| TLS 1.3 + QUIC 建连 | **1-RTT**，复用 **0-RTT** |
| 丢包影响 | 丢包率 ~2% 以上时 **HTTP/2 可能不如 HTTP/1.1**（单连接被放大） |

### L4 · 选择层

- **HTTP/2 收益最大**：页面资源多而小 + RTT 高（移动端、跨地域）。
  **收益最小**：单个大文件下载（本来就一个流）。
- **升级后要撤掉的老优化**：
  **域名分片**（把资源打散到多个域名反而破坏单连接复用，还多几次 DNS + 握手）、
  **雪碧图 / 资源内联**（本来是为了减少请求数，现在请求便宜了，反而损失了缓存粒度）。
  **这一条是「真的上线过」的标志。**
- **gRPC 基于 HTTP/2**：要的是多路复用 + 双向流 + 二进制帧。
- **HTTP/3 的部署现实**：需要 UDP 放行、需要能回落；CDN 层先上最划算。

### L5 · 深水区

1. **Server Push 已被主流浏览器移除**（Chrome 106 起默认关闭）：
   服务端不知道客户端缓存里有什么，经常推重复资源，收益为负。
   替代品是 **103 Early Hints**（提前告知要预加载什么，由客户端决定）。
2. **单连接对负载均衡不友好**：长连接一旦建立就固定在某台后端，
   扩容后新实例分不到流量 —— 需要**请求级负载均衡**或周期性 `GOAWAY`。
3. **QUIC 的 CPU 代价**：用户态收发 + 每个包独立加密，
   **CPU 开销通常比 TCP+TLS 高不少**（GSO/offload 在补，但不如 TCP 成熟）。
4. **HPACK 动态表是连接级状态**：代理必须逐连接维护，内存与实现复杂度都上去了。
5. **0-RTT 可重放**：只能用于幂等请求。
6. **HTTP/2 在丢包时更差**这一条要说得出原因：
   多路复用把所有流押在一条 TCP 上，丢一个包全体等待。

### 背诵指纹（听到就追，**不许把左边这句念出来**）

| 一听就是背的 | 立刻追 |
| --- | --- |
| 「HTTP/2 有多路复用，所以更快」 | 1.1 里浏览器怎么绕过这个限制的？绕完还慢在哪？ |
| 「HTTP/2 解决了队头阻塞」 | 哪一层的队头阻塞？那为什么还要 HTTP/3？ |
| 「HTTP/2 是二进制的，所以效率高」 | 二进制本身省了多少？真正的收益来自哪个特性？ |
| 「HTTP/2 有头部压缩」 | 压的是什么？一个带 Cookie 的头多大？压完多大？ |
| 「HTTP/3 用 UDP 所以快」 | 它把可靠性放哪了？UDP 被限速的网络怎么办？ |
| 「HTTP/2 支持服务端推送」 | 现在还能用吗？浏览器为什么把它去掉了？ |
| 「升级 HTTP/2 只有好处」 | 丢包率 2% 的弱网上呢？域名分片要不要撤？ |
| 「HTTP/2 必须要 HTTPS」 | 协议规定的还是浏览器规定的？版本是怎么协商出来的？ |

### 常见错答

1. **认为 HTTP/2 彻底解决了队头阻塞**（核心失分点）。
2. **不知道 HTTP/1.1 靠多连接绕过串行**，以为 1.1 就是完全串行的一个连接。
3. **认为管道化能用**（响应仍需按序，实际被禁用）。
4. **认为 HTTP/2 在任何网络下都更快**（高丢包下可能更差）。
5. **升级后仍然做域名分片、雪碧图。**
6. **认为 Server Push 是 HTTP/2 的主要卖点**（已被废弃）。
7. **认为 HTTP/3 不可靠**（QUIC 自己实现了可靠与拥塞控制）。
8. **说不出 ALPN**，以为要额外一次协商往返。

### 判卷线

**说得出「队头阻塞有 HTTP 层和 TCP 层两份，HTTP/2 只解决了前者，
所以才有 HTTP/3」，并且答得出升级后该撤掉域名分片的，才算真的会。**
只答得出「二进制、多路复用、头部压缩」三个词的，一律记成背的。
