# 故障排查：这一批是反过来的

别的系列都是**它问你答**。这一批**你问它答**。

它给你一个故障现场（服务是什么、症状、什么时候开始、影响面），
然后闭嘴。你提问、要监控、要日志、要抓包、提假设 ——
它拿着一份**你看不见的真相**回答，而且只回答你问到的。

练的不是「你知不知道这个原因」，是**你会不会问**：
从一句含糊的「变慢了」到根因，中间那条提问链长什么样。

## 一条不能破的规矩

**它不许主动提示下一步该看哪里。** 你不问，它就不说 ——
哪怕你在原地绕十分钟。

这是有意的，也是这一批唯一真正重要的机制：
现实里没有人会在你身边说「你应该看看火焰图」。
**排查能力就是「想得到该问什么」这一件事**，一旦模型开始给方向，
你练的就变成了阅读理解。

想不动的时候有口令 `给个方向`，但它**会计入记账** ——
收尾时你会看到自己是靠几问定位的、其中几次是要来的。

## 每一份都埋了伪线索

真实的故障现场从来不是干净的：同期总有一次无关的发布、
总有几个「看起来相关」的指标在动（它们多半是**结果**不是原因）、
总有一个教科书上的经典嫌疑人在那儿等着你扑上去。

所以每一份的真相里都写着「我埋了哪几条伪线索」，
收尾时它会告诉你**你在每条上花了几问**。

## 怎么用

1. 挑一份，**新开一个空对话**。
2. 把那个文件里 `---` 分隔线**之后**的全部内容复制过去。
3. 它会先给你现场，然后停下 —— **接下来该你开口了。**
4. 中途四个口令：

   | 口令 | 作用 |
   | --- | --- |
   | `给个方向` | 给一个方向，不给答案（**计入记账**） |
   | `公布真相` | 直接讲真相并收尾 |
   | `换一个` | 换一个故障重来 |
   | `复盘` | 立刻收尾产出 |

5. **末尾的真相别自己先读** —— 读了这一份就没得练了。

## 建议的路线

- **第一次做，从 `01` 开始。** 它的诊断链最干净（4 问到底），
  用来熟悉「你问它答」这个形状。
- **然后做 `02`。** 它教的那条（「只有一部分」→ 找共同点）
  是所有排查里复用率最高的一条。
- **`05` 留到后面。** 它的答案在你自己的系统之外（中间设备），
  是这批里最容易卡死的一份 —— 但也最像真实的疑难杂症。
- **`06` 和别的都不一样**，它练的是数据口径，不需要任何系统知识，
  产品和数据的同学也能做。

## 这一批和别的系列的关系

答案本身很多来自[计算机系统](../computer-systems/)那批：
`05` 的中间设备静默丢连接就是
[TCP 卡住的六种形状](../computer-systems/10-tcp-stall.md)里的一种；
`03` 的堆内堆外分家、`04` 的 user/sys/iowait 也都在那批里讲过。

**但练的东西完全不同**：那边练「你知不知道」，这边练「你问不问得出来」。
知道 TCP keepalive 默认 7200 秒，和在一个现场里想到去问「中间有没有防火墙、
它的空闲超时是多少」，是两种能力。**建议先做那批，再做这批。**

## 为什么这么写（几个决定）

- **模型只回答问到的，这条比什么都重要。** 破了它，这一批就退化成
  「读一段故障分析」。所以每一份的铁律第一条都是它，而且写了「一句都不行」。
- **真相里的观测结果列成表，一问一答。** 这样模型回答时不容易前后矛盾 ——
  自洽是这个形状能不能立住的前提（我回头再问一遍，答案必须一样）。
- **允许模型编具体数字，但必须和真相一致。** 不给它编数字的自由，
  现场就假；给太多自由，答案就不唯一。
- **收尾卡片和别的系列完全不同**：不是「覆盖表」，是
  **「你用了几问、哪几问在原地打转、最短路径是几问」**。
  排查的水平就是这个比值。
